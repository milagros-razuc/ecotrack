# Feature 021 Data Model

## Cliente

Existing entity in `clientes`.

| Field | Rules |
|---|---|
| `id` | Existing generated identifier |
| `nombre` | Trimmed, 1-100 characters, globally unique case-insensitively |
| `activo` | Existing default active state |
| `es_plataforma` | Existing platform marker; global audit rows use this client |
| `creado_en` | Existing creation timestamp |

The migration must add an idempotent unique index on `lower(nombre)` after detecting
and resolving historical case-insensitive collisions.

## Usuario administrador inicial

Existing entity in `usuarios`, extended for forced first-login state.

| Field | Rules |
|---|---|
| `id` | Existing generated identifier |
| `username` | Trimmed and lowercased, 3-50 characters, globally unique case-insensitively |
| `password_hash` | bcrypt hash only; never returned or audited |
| `nombre` | Trimmed visible name, existing length policy |
| `rol` | Always `admin` for this feature |
| `cliente_id` | Required relation to the new or existing operational client |
| `token_version` | Existing session invalidation counter |
| forced-change state | New persisted marker set at creation and cleared after password change |
| `creado_en` | Existing creation timestamp |

The migration must add an idempotent unique index on `lower(username)` after
historical collisions are detected and resolved. Reserved normalized usernames are
`platform_admin`, `plataforma`, and `root`.

## Temporary password

An in-memory value generated by the server using CSPRNG, at least 16 characters, with
an explicit alphabet excluding ambiguous `0`, `O`, `1`, `I`, and `l`. It is returned
only in the immediate creation response and is never persisted in plaintext.

## Audit record

One row in `auditoria` inside the same transaction as client and user writes.

| Field | Value |
|---|---|
| `cliente_id` | Platform special client |
| `usuario_id` | Authenticated platform admin |
| `usuario_username` | Authenticated platform admin username |
| `actor_tipo` | `platform_admin` |
| `accion` | Client/admin creation action |
| `entidad` | `cliente` or creation aggregate |
| `entidad_id` | Created client identifier |
| `detalle` | Normalized username, client name, motive, result; no secrets |

## State transitions

1. New admin: forced-change state pending, temporary password valid.
2. First login: returns restricted session and forced-change indicator; operational
   routes remain blocked by persisted state.
3. Password change: validates current password, writes new hash, clears forced-change
   state, increments `token_version`, and invalidates prior sessions.
